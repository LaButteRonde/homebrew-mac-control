# Contrat des plugins Mac Control — version 1.2

Mac Control 1.7.0 parle la version **1.2** du contrat. Ce document dit tout ce qu'un plugin peut envoyer, ce qu'il
reçoit, et ce que fait Mac Control de chaque champ. Le schéma JSON de chaque message et de chaque élément
d'interface est à côté : [`1.2.schema.json`](1.2.schema.json).

Historique : **1.0** (Mac Control 1.0), **1.1** (Mac Control 1.6 : `disclosure`, `tabs`), **1.2** (Mac Control 1.7 :
`sheet`, ce que Mac Control sait faire annoncé dans `initialize`, `toggle` de l'accordéon et `select` des
sous-onglets, notifications avec lien, boutons et `notification/click`).

## 1. Le principe

Un plugin est un programme lancé par Mac Control. Ils se parlent en **JSON-RPC 2.0, un message par ligne** : Mac
Control écrit sur l'entrée standard du plugin, le plugin répond sur sa sortie standard. Ce qu'il écrit sur sa sortie
d'erreur va dans son journal (onglet du plugin, « Journal »). Un message de plus de **1 Mio** coupe le canal : le
plugin est arrêté et relancé.

Le plugin ne dessine jamais lui-même : il envoie un **arbre d'éléments** (`surface/render`), et Mac Control le dessine
avec ses propres composants, dans l'onglet du plugin (`tab`) et dans le panneau sous l'icône de la barre des menus
(`menu`).

**Compatibilité** : deux versions sont compatibles quand leur majeur est le même (1.x). Une version mineure n'ajoute
que des éléments, des champs ou des messages ; tout est facultatif dans ce qu'elle ajoute. Un élément inconnu
s'affiche « composant non pris en charge », un champ inconnu est ignoré, un message inconnu aussi.

## 2. Le paquet

Un plugin est un dossier `<nom>.mcplugin` qui contient au moins `manifest.json` et son exécutable.

```json
{
  "id": "fr.exemple.mon-plugin",
  "name": "Mon plugin",
  "description": "Une phrase qui dit ce qu'il fait.",
  "version": "1.0.0",
  "apiVersion": "1.2",
  "author": "Exemple",
  "executable": "bin/mon-plugin",
  "symbol": "star",
  "surfaces": ["tab", "menu"]
}
```

| Champ | Rôle |
|---|---|
| `id` | Identifiant unique, en notation inversée. Sert à l'acceptation, au dossier de données, aux réglages. |
| `executable` | Chemin relatif dans le paquet ; doit rester dans le paquet et être exécutable. |
| `symbol` | Nom d'un symbole SF Symbols (icône de la liste et de l'indicateur). |
| `surfaces` | `tab` : un onglet dans la fenêtre ; `menu` : une section dans le panneau sous l'icône. |
| `apiVersion` | Version du contrat que le plugin parle. Un autre majeur : le plugin est refusé (« incompatible »). |

Ne rien écrire dans son propre paquet : chaque fichier compte dans l'empreinte (§ 9). Les données vont dans
`dataDir`.

### Où poser un plugin

| Dossier | Pour qui | Acceptation | Relance |
|---|---|---|---|
| `~/Library/Application Support/mac-control/Plugins` | les plugins installés | à chaque changement du paquet | quand le paquet change (et qu'il est réaccepté) |
| `~/Library/Application Support/mac-control/Plugins (dev)` | le développement | une fois, par `id` | **seule, à chaque fichier modifié** |

Un plugin du dossier de développement porte le badge **dév**. S'il a le même `id` qu'un plugin installé, c'est lui
qui est retenu.

## 3. Le cycle de vie

1. Mac Control lance l'exécutable, avec dans l'environnement `MAC_CONTROL_API` (version du contrat, `1.2`) et
   `MAC_CONTROL_DATA_DIR` (dossier de données du plugin, avec la barre finale).
2. Il envoie la requête `initialize` ; le plugin a **5 s** pour répondre.
3. Il envoie la notification `initialized`. **Rien de ce que le plugin envoie avant n'est pris en compte** : le
   premier rendu se fait après.
4. Le plugin vit : il rend, reçoit des événements, met à jour son indicateur.
5. À l'arrêt : requête `shutdown`, **3 s** pour répondre et sortir ; puis SIGTERM, puis SIGKILL 2 s plus tard.

Un plugin qui plante est relancé après 1 s, 5 s puis 30 s ; au 4ᵉ plantage en 10 minutes, il est déclaré « en
panne » jusqu'à ce que l'utilisateur clique « Relancer ».

« **Relancer** » (en haut de l'onglet du plugin) arrête le processus et le redémarre, sans toucher à Mac Control ;
le journal note « relancé à la demande », et l'en-tête affiche « démarré à HH:MM:SS ». Un nouveau processus
repart de zéro : il doit renvoyer son rendu et son indicateur.

## 4. Les messages

### Mac Control → plugin

| Méthode | Sorte | Paramètres | Réponse attendue |
|---|---|---|---|
| `initialize` | requête | `InitializeParams` (ci-dessous) | `{"apiVersion": "1.2", "plugin": {"id", "name", "version"}}` |
| `initialized` | notification | aucun | — |
| `ui/event` | requête | `{"surface", "node", "kind", "value"?}` (§ 6) | `{}` sous **10 s**, ou une erreur |
| `surface/visibility` | notification | `{"surface": "tab"\|"menu", "visible": bool}` | — |
| `appearance/changed` | notification | `{"appearance": "light"\|"dark"}` | — |
| `notification/click` | notification | `{"id"?, "action"?}` (§ 8) — depuis 1.2 | — |
| `shutdown` | requête | aucun | `{}` |

`InitializeParams` :

```json
{
  "apiVersion": "1.2",
  "regie": {"version": "1.7.0"},
  "locale": "fr-FR",
  "appearance": "dark",
  "dataDir": "/Users/…/Library/Application Support/mac-control/Data/fr.exemple.mon-plugin/",
  "capabilities": {
    "nodes": ["stack", "section", "text", "status", "toggle", "button", "picker", "time", "textField", "prompt",
              "countdown", "list", "progress", "divider", "disclosure", "tabs", "sheet"],
    "events": ["press", "toggle", "select", "change"],
    "features": ["notify.url", "notify.actions", "notification/click"]
  }
}
```

`capabilities` (depuis 1.2) dit ce que **cette** version de Mac Control sait faire : le plugin s'adapte au lieu de
deviner (par exemple, une feuille si `nodes` contient `sheet`, sinon une section dans la page). Une version 1.1
n'envoie pas ce champ : son absence veut dire « 1.1 ou avant ».

`surface/visibility` dit si l'onglet est à l'écran, ou si le panneau est ouvert : un plugin peut ne calculer que ce
qui se voit. Après un redémarrage, Mac Control renvoie la visibilité et l'apparence du moment.

### Plugin → Mac Control (notifications)

| Méthode | Paramètres | Effet |
|---|---|---|
| `surface/render` | `{"surface": "tab"\|"menu", "root": <élément>}` | Remplace l'arbre de cette surface (au plus 10 fois par seconde, le dernier gagne). |
| `status/set` | `{"symbol"?, "tint"?, "label"?, "priority"?}` | L'indicateur dans la barre des menus. Sans `symbol` : pas d'indicateur. |
| `notify` | `{"title", "body", "id"?, "url"?, "actions"?}` | Une notification macOS (§ 8). |
| `log/write` | `{"level": "info"\|"warning"\|"error", "message"}` | Une ligne dans le journal du plugin. |

Une surface non déclarée dans `surfaces` est ignorée (avec une ligne au journal).

### Erreurs

Une réponse d'erreur à `ui/event` (code **-32000**) montre son `message` à l'utilisateur sous le composant : l'écrire
pour un humain. -32601 : méthode inconnue ; -32602 : paramètres invalides ; -32001 : version incompatible (réponse à
`initialize`).

## 5. Les éléments d'interface

Chaque élément est un objet JSON avec un `type`. `id` est obligatoire pour les éléments qui envoient un événement
(il revient dans `ui/event` sous `node`), facultatif pour les autres ; deux frères ne doivent pas avoir le même `id`.
Un élément dont un champ obligatoire manque devient « non pris en charge » sans emporter le reste de l'arbre.

| `type` | Champs (`?` = facultatif) | Événement envoyé | Depuis |
|---|---|---|---|
| `stack` | `id?`, `axis?` (`vertical`\|`horizontal`), `children` | — | 1.0 |
| `section` | `id?`, `title`, `footer?`, `children` | — | 1.0 |
| `text` | `id?`, `text`, `style?` (`body`\|`secondary`\|`title`\|`monospace`) | — | 1.0 |
| `status` | `id?`, `symbol`, `tint?`, `text` | — | 1.0 |
| `toggle` | `id`, `label`, `value`, `disabled?`, `help?` | `toggle`, valeur : le nouvel état (bool) | 1.0 |
| `button` | `id`, `label`, `symbol?`, `role?` (`normal`\|`primary`\|`destructive`), `disabled?` | `press`, sans valeur | 1.0 |
| `picker` | `id`, `label`, `options` (`[{id, label}]`), `value` | `select`, valeur : l'`id` de l'option | 1.0 |
| `time` | `id`, `label`, `value` (`"HH:MM"`) | `change`, valeur : `"HH:MM"` | 1.0 |
| `textField` | `id`, `label`, `value`, `placeholder?` | `change`, valeur : le texte (à la validation) | 1.0 |
| `prompt` | `id`, `title`, `message?`, `field` (`{label, value, placeholder?}`), `confirm`, `cancel` | `change` (texte) ou `press` `{"action": "cancel"}` | 1.0 |
| `countdown` | `id?`, `until` (date ISO 8601), `prefix?` | — | 1.0 |
| `list` | `id`, `rows` (`[{id, title, subtitle?, symbol?, trailing?, actions?}]`), `empty` | `press`, valeur : `{"row", "action"}` | 1.0 |
| `progress` | `id?`, `value`, `total?`, `text?` | — | 1.0 |
| `divider` | `id?` | — | 1.0 |
| `disclosure` | `id`, `title`, `expanded?`, `children` | `toggle`, valeur : ouvert (bool) — depuis 1.2 | 1.1 |
| `tabs` | `id`, `selected?`, `tabs` (`[{id, title, symbol?, children}]`) | `select`, valeur : l'`id` de la page — depuis 1.2 | 1.1 |
| `sheet` | `id`, `title`, `presented?`, `children` | `toggle` `false` quand l'utilisateur la ferme | 1.2 |

`tint` : `accent`, `warning`, `critical`, `neutral`. Une action de ligne (`actions`) : `{id, label, symbol?, role?}`
— `role: destructive` demande confirmation. Un `button` `destructive` aussi.

### Pendant l'envoi

Un `toggle`, `picker`, `time`, `textField` ou `button` reste grisé, avec un indicateur, jusqu'à la réponse du plugin.
Le plugin répond, **puis** renvoie un rendu avec la nouvelle valeur : c'est le rendu qui fait foi. Une erreur laisse
l'ancienne valeur et affiche le message.

## 6. Accordéon, sous-onglets : ce que font `expanded` et `selected`

`expanded` (accordéon) et `selected` (sous-onglets) sont **l'état de départ** :

- au premier affichage, l'accordéon est ouvert si `expanded` est `true` (fermé sinon), et la page montrée est celle de
  `selected` (la première sinon) ;
- dès que l'utilisateur ouvre, ferme ou change de page, **son choix l'emporte**, gardé par `id` jusqu'à ce que Mac
  Control quitte. Un nouveau rendu avec un autre `expanded` ou `selected` **ne le change pas** ;
- chaque geste envoie un `ui/event` (depuis 1.2) : `{"node": "<id>", "kind": "toggle", "value": true|false}` pour
  l'accordéon, `{"node": "<id>", "kind": "select", "value": "<id de la page>"}` pour les sous-onglets. Mac Control
  n'attend pas la réponse : le choix est déjà affiché. Un plugin qui veut retrouver l'état au prochain lancement de
  Mac Control le garde, et le renvoie en `expanded` / `selected`.

Le panneau sous l'icône montre une seule page des sous-onglets, sans sélecteur : toujours celle de `selected`.

## 7. La feuille : `sheet` (depuis 1.2)

Une fenêtre par-dessus l'onglet du plugin, pour un réglage ponctuel (identifiants, une confirmation avec des champs).

```json
{"type": "sheet", "id": "connexion", "title": "Se connecter", "presented": true, "children": [
  {"type": "textField", "id": "utilisateur", "label": "Utilisateur", "value": ""},
  {"type": "button", "id": "connecter", "label": "Se connecter", "role": "primary"}
]}
```

- **C'est le plugin qui l'ouvre et la ferme**, avec `presented` : un bouton de la page envoie `press`, le plugin
  répond et rend la feuille avec `presented: true` ; il la ferme en la rendant avec `presented: false` (ou en la
  retirant de l'arbre).
- Ses éléments envoient leurs événements comme dans la page.
- L'utilisateur peut la fermer (« Fermer », Échap) : le plugin reçoit `{"node": "<id>", "kind": "toggle", "value":
  false}`. Elle reste alors fermée, même si un rendu en route dit encore `presented: true`, **jusqu'à ce que le
  plugin la rende avec `presented: false`** ; la fois suivante, `true` la rouvre.
- Une feuille peut se placer n'importe où dans l'arbre ; elle ne prend pas de place dans la page.
- Elle ne s'affiche pas dans le panneau sous l'icône (trop petit) : n'y mettre que ce qui se fait sans elle.

## 8. Les notifications

```json
{"jsonrpc": "2.0", "method": "notify", "params": {
  "title": "Nouveau message", "body": "Marie : la réunion est déplacée",
  "id": "message-42", "url": "https://exemple.fr/messages/42",
  "actions": [{"id": "lu", "title": "Marquer lu"}, {"id": "repondre", "title": "Répondre"}]
}}
```

- Le titre affiché est « <nom du plugin> — <title> ». La permission est demandée à la première notification.
- `url` (depuis 1.2) : ouverte par un clic sur la notification. **`http` et `https` seulement** ; une autre adresse
  est ignorée.
- `actions` (depuis 1.2) : des boutons sur la notification.
- Un clic envoie au plugin `notification/click` (depuis 1.2) : `{"id": "message-42"}` pour un clic sur la
  notification, `{"id": "message-42", "action": "repondre"}` pour un bouton. `id` est absent si `notify` n'en avait
  pas. Si le plugin ne tourne plus à ce moment, le clic est perdu (l'`url` s'ouvre quand même).

## 9. L'acceptation (`acceptations.json`)

Un plugin qui n'est pas livré avec Mac Control ne tourne pas tant que l'utilisateur ne l'a pas **accepté** (onglet du
plugin, « Examiner… »). La feuille d'acceptation montre l'identifiant, l'auteur, la version, l'exécutable et sa
signature.

**Ce qui est contrôlé (depuis Mac Control 1.7.0)** : l'empreinte SHA-256 de **tout le paquet** — le chemin, la
nature (fichier, exécutable, lien) et le contenu de chaque fichier. Elle est stockée dans
`~/Library/Application Support/mac-control/acceptations.json` sous la forme `"<id>": "paquet:<empreinte>"`.

**Quand l'acceptation est redemandée** : dès qu'un fichier du paquet est modifié, ajouté, retiré, renommé, ou change
de droit d'exécution. Mac Control surveille les dossiers de plugins en continu (jusqu'au fond des paquets) : le
plugin s'arrête aussitôt et attend un nouvel accord, avec une phrase qui dit qu'il a changé. Une simple date de
modification (`touch`) ne change pas l'empreinte.

**Ce qui n'est pas compté**, parce que ça change sans que personne touche au plugin : `.DS_Store` (le Finder),
`__pycache__` (Python) et `.git`.

**Avant 1.7.0**, seul l'exécutable était contrôlé : un exécutable qui lance un script laissait changer le script sans
rien redemander. Les plugins acceptés sous une version antérieure sont redemandés une fois après la mise à jour.

**Dossier de développement** : un plugin de `Plugins (dev)` s'accepte une fois, par son `id` (stocké `"<id>":
"dev"`) ; ensuite il est relancé à chaque fichier modifié sans rien redemander. Déplacé dans le dossier normal, il
est redemandé.

## 10. Développer un plugin

1. Travailler directement dans `~/Library/Application Support/mac-control/Plugins (dev)/<nom>.mcplugin` (un vrai
   dossier : un lien symbolique n'est pas suivi) ; l'accepter une fois.
2. Enregistrer un fichier : le plugin redémarre seul, un instant après ; l'en-tête de son onglet affiche « démarré à
   HH:MM:SS ». « Relancer » le fait à la demande.
3. Lire ce que Mac Control annonce dans `initialize.params.capabilities` avant d'envoyer un élément récent.
4. Une fois prêt, le déplacer dans `Plugins` : il est accepté avec l'empreinte de son paquet.

Exemple complet, en bash et `jq` : `compteur.mcplugin` (dans le dépôt, `Exemples/`). En Swift : la bibliothèque
`MacControlKit` (`PluginContext.capabilities`, `supports(node:)`, `onNotificationClick`, `notify(title:body:id:url:actions:)`).
